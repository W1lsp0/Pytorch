# 三、新版出现了一个可以明确构造的恢复死锁

这是本轮最需要优先修复的方法问题。

## 1. 现在的效用阈值实际是 `HistPerf < 0.74`

正文明确规定：

\[

因此：

\[

\quad\Longleftrightarrow\quad

HistPerf_k^{(t)}<0.74.

\]

也就是说，历史效用低于 **0.74** 就开始累计审查条件，而不是低于 0.26。ispa2026_submission(6)

你的冻结参考集合只允许上一轮处于 NORMAL／SUSPECT 且风险较低的客户端进入。缺少必需的 peer 证据时，审计被标记为不完整，历史与风险状态保持不变。ispa2026_submission(6)

\[

\text{全部 QUARANTINE}

\Rightarrow

\mathcal R_t=\varnothing

\Rightarrow

\text{peer 审计不完整}

\Rightarrow

\text{历史与风险冻结}

\Rightarrow

\text{无人恢复}.

\]

**这是一个恢复死锁：不是暂时没有更新，而是恢复本身依赖一个已经无法重新产生的参考集合。**

而且，这个状态仍然可能满足“永久误封率为零”——没有人进入 BLACKLIST，但所有正常客户端都无法继续贡献。这也进一步说明最终封禁率不能代替实际参与和恢复指标。

# 九、下一轮实验应按这个顺序做，而不是继续扩大论文规模

## 第一阶段：先做控制逻辑测试，不需要完整训练

最值得先完成的是以下测试：

| 测试 | 必须检查的行为 |
| --- | --- |
| 所有候选都不通过某层门槛 | 该层严格保持不变，不从隔离客户端回填 |
| 所有客户端同时隔离 | 存在明确、可执行的恢复路径，而不是永久冻结 |
| 持续瞬时风险为 1 | 状态事件时间与 EMA、阈值和持续计数一致 |
| 稳定正常贡献但历史尚未积累 | 不因启动阶段阈值设计造成无解释的集体隔离 |
| 零更新、单个可用客户端、缺失 peer | 行为有明确定义，且不会污染正常客户端状态 |

这些测试通过以后，再运行完整联邦实验。否则新增 GPU 实验可能只是重复观察一个尚未定义一致的算法。

## 第二阶段：补最能证明核心机制的实验
