# ISPA 全文检查

> 历史检查记录：以下内容针对按原PDF恢复之前的10页ISPA稿，不是当前稿件的状态清单。后续核对发现，其中部分矛盾来自修改时加入的新定义。当前已按用户指定的 `PRICAI_2026_paper__46.pdf` 恢复方法及实验口径；恢复范围见 `ISPA恢复说明.md`。原稿已有的指标及图表疑点，不应与修改引入的问题混为一谈。

检查对象：`ispa2026_submission.tex`、当前 10 页 PDF、被引用的共享图文件及 `ispa2026_references.bib`。

本轮只检查，不修改论文标题、正文、公式、图表或结果。判断依据是当前稿件内部的一致性，不以本机消融代码否定另一台机器上的 Intel TDX 实验。没有重新运行训练，也没有逐条核验全部文献原文。

## 一、已确认的实质性不一致

### 1. 图4的状态迁移不是正文规定的状态迁移

- 位置：正文第165行；PDF第5页图4；`../Figure/fig4_state.pdf`。
- 正文：NORMAL → SUSPECT → QUARANTINE → BLACKLIST；永久封禁要求 QUARANTINE 后连续四轮 RiskEMA ≥ 0.90。
- 图中：存在 SUSPECT → BLACKLIST 的直接箭头；另有 NORMAL → QUARANTINE，触发描述只是 HistPerf declines。
- 图中还把 TEE attestation revoked 放在永久封禁迁移附近，正文的相应迁移依据则是持续风险。
- 影响：图和文字定义了不同算法。必须依据实际实验版本统一迁移条件，不能只美化图形。

### 2. 图6(b)的风险曲线违反正文给定的 EMA 上界

- 位置：第134、163、276行；PDF第8页图6(b)。
- 正文：RiskEMA 初值0，βr=0.85，瞬时风险被截断在[0,1]。
- 因此即使每轮瞬时风险均为1，也有 RiskEMA(t) ≤ 1−0.85^t。第3、5、8轮上界分别为0.3859、0.5563、0.7275。
- 图中 C4 在最初几轮已接近1，C0 在第8轮附近约0.95，不能由这一递推得到。
- 处理：核对绘图使用的真实状态变量、初值、系数与采样单位，依据同一次运行日志统一公式和曲线。不能手工修改曲线以迁就公式。

### 3. 图6(b)把0.26用于 HistPerf，正文却用于其补数

- 位置：第165行；图6(b)的 Soft Isolation (HistPerf < 0.26)。
- 正文定义 u=1−HistPerf，u>0.26 等价于 HistPerf<0.74；与图中的 HistPerf<0.26 不同。
- 两者不仅标签不同，还会产生不同的客户端状态。需核对实际执行的判据。

### 4. 图7(a)与正文的攻击指标定义冲突

- 位置：第286、288行；PDF第9页图7(a)。
- 正文明示 Sign-Flipping、Gradient Scaling 是无目标攻击，不计入 targeted ASR。
- 图中同样把两者标为 Untargeted，却与 Clean-Label Backdoor 共用 Attack Success Rate (ASR) 纵轴。
- 处理：先确认这些柱子的分子、分母与原始统计含义。若是无目标攻击的另一定义，必须给出定义并与目标ASR区分；不能直接改轴名称沿用数字。

### 5. 图7(b)展示50轮，正文统一声明每次运行30轮

- 位置：第274、286行；PDF第9页图7(b)。
- 图中第30轮后仍有曲线与采样点，一直延伸到50轮。
- “后续变化很小”解释了收敛形状，不能说明30轮实验如何产生31—50轮记录。
- 若这项消融确实独立运行50轮，应明确其预算例外；若只有30轮日志，就只画真实记录。

### 6. 图6(a)没有正文承诺的三种攻击独立ASR曲线

- 位置：第288、292行；PDF第8页图6(a)。
- 正文两次说三种攻击的ASR分别保留在收敛曲线中。
- 实际图例只有一条 Backdoor ASR，无法知道它是标准后门ASR还是三种攻击的宏平均。
- 图例还保留了 Accuracy (Trust Flow, from Fig.10)，但当前稿件只有8个编号图。这是旧图编号残留。
- 处理：明确现有曲线来源与口径；有真实三组日志时再补三条曲线。

### 7. 图1、图3的系统接口与正文存在歧义，图3阶段数也不同

- 位置：第76、100、105、417行；图1、图3。
- 正文明确不使用隐藏单客户端更新的密码学安全聚合；图1、图3却出现 Secure Aggregation。
- 如果只是泛指“经过安全审计的聚合”，应改为更具体的名称，避免被理解为密码学 secure aggregation。
- 正文和图3图注写 four-stage，图内却列 Stage 1—Stage 5。可统一为“四个决策阶段加一个反馈阶段”，或按实际流程统一数量。
- 图1还有 TEE-Protected Server Enclave，而部署段主要交代客户端TDX路径，服务器的这项边界未说明。

### 8. “校准独立于当前客户端”的声明不由现有集合定义保证

- 位置：第199、232行。
- 校准集合 T 按准入资格和上轮风险定义，当前接受检验的客户端 k 可能属于 T。
- 此时用 T 的统计量确定 median+3MAD，仍然包含 k 的当前证据，不能称为 independent of the candidate under test。
- 应核实实际是否使用 T\{k} 或独立校准数据，再按实际算法描述。

## 二、算法描述需要补全或核实

### 9. 层阈值可大于所有客户端可能获得的最高分

- 位置：第169—171、199—217、278行。
- 现有因子及正指数给出 RawScore≤1。
- θ=0.4+1.2S，S∈[0,1]，所以 θ∈[0.4,1.6]。只要 S>0.5，就一定没有客户端通过。
- 稿件定义了空集时选择最高分客户端的回退，所以算法未必没有输出；但这些层会必然进入单客户端回退。
- 需要核对实际系数，并报告敏感度、通过人数和回退频率，才能解释分层筛选究竟如何工作。不能直接凭期望效果修改系数。

### 10. 隔离状态如何改变聚合资格没有写入集合定义

- 位置：第165、208、217行。
- 当前幸存集合从 admitted set A 中按 RawScore筛选，空集回退也在 A 中选最大分。
- 文中没有清楚定义 A 是否已排除 QUARANTINE/BLACKLIST，或这些状态如何更新 A。
- 若 A 只是通过TEE准入的客户端，回退可能重新选到被隔离的客户端；若 A 是状态筛选后的集合，需要明确写出。
- 还缺少 A 为空、T 为空时 C_base 如何计算等边界处理。

### 11. 无proxy分支只说明了参考方向替代，未说明探针如何继续计算

- 位置：第140、227—232、240、417行。
- trusted-peer fallback 可以代替 g_root，但 clean-loss probe 和 activation probe 仍使用服务器proxy样本。
- 无proxy时应说明这些通道被停用、被替代，还是仍依赖其他数据，以及相应校准规则。
- 这不否定已有proxy条件下的实验；问题在于“无proxy仍按相同流程运行”还缺少完整方法定义。

### 12. 冷启动、首轮证据和当前轮门控的时序还不够明确

- 位置：第161、163、165、169—171行。
- 冷启动段说首轮证据留到下一次状态更新；递推与评分公式使用当前轮 HistPerf、RiskEMA。
- 首轮 provisional privilege 未给出独立计算方式，也未明确它是否更新当前EMA。
- 当前强风险的隔离规则仅写为 SUSPECT → QUARANTINE，NORMAL 客户端突然遭遇强异常时是否有额外当前轮限制，需要结合真实实现写清楚。
- 应用简洁的轮次顺序或伪代码说明，避免读者自行猜测。

### 13. TDX证明时序与隐私验证接口仍需说明

- 位置：第94、113、238、261行。
- 第113行把含 update digest 的 Quote 放在 initialization，随后才开始描述本地训练；当轮更新尚未生成时，其摘要如何绑定没有解释。
- 建议区分初始化工作负载准入与每轮训练结束后的更新/报告绑定，写清验证发生在哪一步。
- privacy-aware verification 在摘要和方法中多次出现，但具体检查哪些统计量、如何验证、服务器可见哪些字段尚不完整。
- 此项并不是判定TDX未实现，也不是否定11ms、12—15ms测量；需要补的是让读者能够理解的执行接口和测量范围。

## 三、需要实验记录核对的事项

### 14. Table3的FPR/TPR无法按当前描述直接还原为整数计数

- 位置：第261、286、288、388—391行。
- 主设置每次14个正常客户端、6个恶意客户端，共10个平台—种子运行。
- 如果Table3的FPR也使用最终永久封禁口径，等分母运行的均值应为总误封人数/140，步长约0.7143个百分点；0.15%、2.10%、18.25%不能由此按两位小数得到。
- 如果TPR按每次6个恶意客户端的最终检出人数计算，步长为1/60，即约1.6667个百分点；95.12%、48.33%、21.05%也不能按此口径还原。
- 若消融使用逐轮计数、不同重复次数或其他分母，结果可能有解释，但必须单独定义。不能在没有原始人数前直接认定百分比错误。

### 15. Table2新增三种方法的数值来源与“统一协议”声明需要核实

- 位置：第261、288、338—340行。
- FLAME、FLDetector、FreqFed 已有方法论文引用，但引用只能证明方法来源，不能证明表内准确率、ASR和标准差来自当前统一协议。
- 若三行来自本项目复现实验，需要对应配置和日志；若来自各原论文不同设置，不能同时称为共享当前数据、模型、攻击时序和十次运行的严格对比。
- 本次不更改用户指定的数值，也不把它们认定为原论文的已验证结果。

### 16. 500张服务器数据的来源和最终测试集规模不明确

- 位置：第261行。
- 文中把50,000张训练图像全部分给5000共享池与45,000独占样本，另说500张proxy来自 held-out CIFAR-10 reference partition。
- 需要说明这一reference partition从哪部分划出，以及最终评测还剩多少样本，才能复现实验且核实三者互不重叠。
- 目标ASR测试子集还未明确是否排除原本属于目标类别的样本，建议同时给出每种攻击的评测样本数。

### 17. 消融已有，但若干结论在当前稿件中找不到对应证据

- 位置：第48、63、286、409、411行；Table3、图7、图8。
- Table3已有单流、HistPerf-only、双流比较，不能说“没有双流消融”。
- 但引言强调“先积累良好历史、再突然攻击”，当前主协议明确所有攻击从每轮训练开始就持续启用；这组主实验不能单独证明延迟攻击响应优势。
- 88.33%逐轮恶意覆盖率、14.79%正常review率，在所引用图7、图8中都没有对应展示或计数定义。
- β_fusion=2.0被称为最佳观察到的accuracy–ASR平衡，但当前稿件没有列出其他取值的比较。
- 若这些证据已在别处完成，应补充对应结果位置与口径；不能由图7、图8自动推得。

### 18. 硬件重复与种子重复需要区分

- 位置：第261、286、288行。
- 文中说两种硬件各5个种子，汇总10个平台—种子运行，但paired host configurations没有交代具体配置。
- 如果两台平台使用相同5个种子，10次运行不等于10个独立随机种子；可以汇总，但应说明配对方式和标准差计算单位。
- TDX路径、GPU型号、监测开销已写入；进一步需要CPU/TDX软件栈与11ms、12—15ms各自起止点，便于复现已有测量。
