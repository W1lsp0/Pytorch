# TMAA-FL: 基于旁路伴随与多维矩阵的可信边缘联邦防御框架 🛡️

（Framework Details & Experimental Defense Logics）

## 🌟 核心设计哲学 —— “球员与裁判分离 (The Sidecar Pattern)”

在传统的联邦学习（如使用 `Client.fit()`）中，存在着极度脆弱的 **“默认信任”**：架构假设并盲从每一个本地的 PyTorch 计算脚本都是“诚实训练”。这在完全分布式的开放网络中，导致系统能够被本地投毒和设备劫持随意瓦解。

本平台将这种信任模型拔高为 **“验证后信任 (Trust but Verify)”**。为了既能审计防篡改，又不对客户资料原文件“越界获取”(Data Privacy)，我们创造性地采用了 **云原生伴随架构模式 (The Sidecar Pattern)**。

### 监控器(Referee) 与 训练器(Athlete) 隔离
- **Worker (不可信工作区)：** 负责执行参数矩阵提取 (如本地 ResNet 训练)，它不知道自己被监控。若它被病毒附着篡改底层，也不具有关闭裁判机制的权限。
- **TMAA (可信锚点区)：** 运行在英特尔 SGX 或高权限沙箱 (TEE) 内，独立内存驻留。像影子般锁定该进程，用 OS Hook 吸附在其身侧收集不可篡改的“行为证据”。整个交互流程表现为：客户端计算梯度 $\rightarrow$ 伴随进程扫描形成《报告日志》 $\rightarrow$ 硬件 TEE 私钥进行 RSA/ECDSA 签名 $\rightarrow$ 捆绑网络发送至 Server 的大兵团聚合处。

## 🏗️ 防御战神：TMAA 四维监控矩阵与标量审计体系

本项目的最强安全大脑集成为四级解耦防御，由浅入深层层把关（客户端侧代码集中在 `Client/tmaa/inspector.py` 中体现）。

### Layer 1: 系统完整性 (System Integrity) —— 防篡改与抗女巫的静态硬桩
- **防伪造**：程序启动的毫秒间，扫描自身以及核心训练代码段的跨平台哈希值与签名档。
- **抗女巫**：在通信握手注册时使用硬件公私钥对挑战，服务器以此生成一次性的不可伪造指纹。从而让那些试图用一个算网络大显存来“分身并伪装为100个客户端的节点”原形毕露。只有这个层级没有报警的系统，才能被称为安全基线。

### Layer 2: 行为动力学指纹 (Behavior Dynamics) —— 防止“随机装死”与“计算伪装”
即使程序不曾被篡改，依然会有不愿真金白银贡献算力的“Lazy Client”。
- **硬件消耗监控**：TMAA 每秒读取进程 GPU_Utilization / RAM_Volatilities 波形波动方差幅度。
- **拦截表现**：对于完全没做过前向和反向传播就凭空产生乱码梯度的人员，TMAA 会记录一个直线而非“健康且周期的锯齿形运算波”。直接通过吞吐量判断：你的“上传包更新速率”，与你填报的 3080GPU 硬件能力完全不同频。

### Layer 3: 隐私保护数据审计核心 (Zero-Knowledge Data Audit) (核心重构亮点)
**怎么在既不侵犯隐私，不让服务器索要任何一个特征张量的情况下，审计数据的健康和投毒倾向？** TMAA 采用了极其巧妙的无量纲数学分析方式：
1. **信息熵 (Shannon Entropy) $\rightarrow$ 对应防范 Non-IID 问题**
   本地根据统计到的标签集合生成宏观标量。如果这个值特别低，意味着它家只有“猫”的分类数据，属于严重偏科，这种人在接下来的策略中会导致极端的偏态特征。
2. **聚类分离度 (Cluster Separability) $\rightarrow$ 对应防范 隐藏后门/Trigger投毒**
   无需回传图片。在本地提取的深层输出嵌入式特征执行基于 K-Means (k=2) 的 Silhouette 轮廓计算。对于包含隐蔽触发器的类别，必然因异质混合在特征面撕裂成为显著的双峰分离特征 (如分值 > 0.6)。这项结果可以直接把投毒攻击者揪出来记录在案！
3. **唯一性碰撞查验 (Uniqueness Ratio) $\rightarrow$ 对应防范 复制造假 (Data Duplication)**
   提取特征散列化计算全数据集重复程度，让用少量图片凑数应付训练的节点自动爆出。
*以上四项全部会套用“拉普拉斯噪声”(DP Noise)，哪怕是统计报告也不会泄密用户数据的实际样貌。*

### Layer 4: 网络围栏警戒 (Network Perimeter)
- TMAA 并行锁定操作系统的网络句柄 (Session Sockets)，当探测到进程与服务端及其他合规节点以外的不明 C2 连接或异常 P2P 探查时，视作“共谋攻击合流”，直接报警切断。

## 🌐 决战紫禁之巅：实验验证与策略是如何精准聚合的？

所有带着“数字签名证明与四层异常值审查结果”的终端报告传到了服务器策略中心进行判决（逻辑体现至 `server/strategy.py` 以及刚被重构剥离出来的：`trust_manager.py` / `contribution.py` 等）。

这里的神仙打架，不再是传统的计算一下相加求平均 (FedAvg) ，而是真正的“信任流与数学裁判”。

### Step 1: TrustScore 的门限赋予与加权一致性验证
每个人的 `TrustReport` 的每一项负能量异常因子（L2/L3）都会拉低一个人的天然出身评估：`TrustScore`。
在评估上传的几百万参数矩阵组成的梯度“真伪和方向健康”度时：
- 我们计算 **“共识参照系 (Reference Gradient)”** 时，并不是按照人头算，而是按 `TrustScore` 来加权的。这就使得即便一群坏人（比如投毒者）凑在一块上传极端的反方向模型，因为它们这批人因为 L2 表现或系统信任不行而导致发言声音极小，基准大盘将不可被扭转地被“健康少数派”死死钉住！

### Step 2: ContentScore 纯能力值洗礼
抛开你是好是坏，“这轮传上来的作业到底对模型的贡献提升如何？”基于刚才稳定的真理大局进行“**贡献度和方向偏离度余弦算法**”。再用具有强烈惩戒性的 $Relu$ 加起拔作用的根号计算将其融汇为不含历史成见的单轮表现分 (`ContentScore`)。

### Step 3: EMA 流更新长期记忆口碑 (`HistPerf`)
把这一轮的测验成绩放到长河里，表现高于所有人平均水平的大牛将在 Sigmoid 赋型后获得荣誉增量；利用 EMA 存为 `HistPerf`，保证“平时老老实实做人的人，偶尔一轮设备不好依然能够依靠资历保持特权”。

### Step 4: 细作绝杀的高精度分层过滤聚合 (Layer-differentiated Operation)
服务器不再是一锅端掉那些参数。而是深入模型内各个架构：
- 我们根据特征梯度矩阵范数的厚度与顺位的深度算出每一个浅提取网络、深重压网络的敏感度（`SensitivityScoret`）。
- **最隐秘的后门投毒，必然藏在特征提取背后的隐蔽长尾决策深度层。因此我们要对这类深埋神经元设立极为苛刻的接纳阈值。**
- 每个人的话语权分数（$CompositeWeight$）会在迭代此层的时候作比对：一旦由于你口碑不好且偏科导致低于本深层的警戒阈值要求，系统将**强行将其剥去**（该层对你的模型置零或忽略收束）。于是我们完美保住了他无害的特征基础模型，绝杀了那些暗地里携带深水鱼雷企图改动核心权重的偷渡者。

## 🏁 How to Check 编译与验证

该套双流引擎与多分类 Sidecar 风控全部以纯粹的高内聚代码被整合为了上述多个 py 文件独立呈现。在算力受限但想单独在编译层进行验算的话，我已经利用 Linux 下您的原配核心校验跑通：

```bash
/root/miniconda3/envs/pytorch/bin/python -m py_compile ./server/*.py
```
如要重演大型仿真或修改聚合参数比例（如调整 $\alpha$, $\beta$, $\gamma$的偏重），可直接移步带有双卡/多卡的机台或修改 Server 后按部就班通过 `run_simulation.py` 发射验证。您在终端将能一览无遗上述拦截过程。
