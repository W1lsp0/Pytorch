# 5.2 实现 信誉系统动态更新

> 代码对齐版本（2026-03-09）  
> 对齐实现：`server/trust_manager.py`（`update_history` + `update_risk_history`）

## 1. 双流正交更新总览

当前实现不是单一 `HistPerf` 更新，而是两个通道并行：

- 历史信誉流：更新 `HistPerf`
- 风险流：更新 `RiskEMA` 与处置状态

## 2. 历史信誉流（内容驱动）

### 2.1 更新信号

先做相对竞争信号：

$$
z_k=\frac{ContentScore_k-\mu_{content}}{\sigma_{content}+\varepsilon}
$$
$$
Signal_k^{rel}=\sigma(z_k)
$$

再做绝对底线信号：

$$
Signal_k^{abs}=clip\left(\frac{ContentScore_k-b}{s},0,1\right)
$$

融合：

$$
Signal_k^{upd}=w_{rel}\cdot Signal_k^{rel}+w_{abs}\cdot Signal_k^{abs}
$$

当前参数：

- `w_rel=0.40`
- `w_abs=0.60`
- `b=0.40`
- `s=0.30`

### 2.2 EMA 更新

$$
HistPerf_k^{(t)}=\beta_h\cdot HistPerf_k^{(t-1)}+(1-\beta_h)\cdot Signal_k^{upd}
$$

当前 `beta_h = 0.8`。

### 2.3 `HistPerf` 生成过程图（Mermaid）

```mermaid
flowchart TD
    C[输入 内容分数 ContentScore_k] --> M1[计算 mu_content = mean(content_scores)]
    C --> M2[计算 sigma_content = std(content_scores)+eps]
    C --> Z[标准化 z_k = (ContentScore_k - mu_content)/sigma_content]

    Z --> R[相对信号 Signal_rel = sigmoid(z_k)]
    C --> A[绝对信号 Signal_abs = clip((ContentScore_k-b)/s, 0, 1)]

    R --> U[融合信号 Signal_upd = 0.4*Signal_rel + 0.6*Signal_abs]
    A --> U

    H0[历史输入 HistPerf_k(t-1)] --> E[EMA更新]
    U --> E
    E --> H1[历史输出 HistPerf_k(t)]

    H1 --> S{HistPerf < 0.26 ?}
    S -->|是| T[soft_streak += 1]
    S -->|否| Q[soft_streak = 0]
    T --> I[soft_isolated = (soft_streak >= 5)]
    Q --> I

    K1[注释: 阈值0.26与连续5轮是当前代码参数]:::note -.-> S
    K2[注释: soft_isolated是可恢复状态 不是永久封禁]:::note -.-> I

```

### 2.4 Hist 软隔离

若 `HistPerf < 0.26` 连续 `5` 轮，则命中 Hist 软隔离。

## 3. 风险流（独立于 Hist/Raw）

### 3.1 多通道瞬时风险

代码综合多通道风险（报告风险、梯度方向偏离、探针离群、像素统计、触发器亲和、符号一致性、peer 风险等），取峰值形成 `instant_risk`。

### 3.2 风险 EMA

$$
RiskEMA_k^{(t)}=\beta_r\cdot RiskEMA_k^{(t-1)}+(1-\beta_r)\cdot Risk_k^{inst}
$$

当前 `beta_r = 0.85`，并有高置信条件下的 `instant_kill_switch`。

### 3.3 处置升级

- `risk_soft_streak` 达标后进入 `risk_isolated`
- C1 快封通道：触发器异常持续命中
- C2 漂移通道：`probe/peer/grad` 组合持续命中并带记忆分
- `risk_hard_streak` 达标直接黑名单
- 长期软隔离在满足跨通道证据时可升级黑名单

## 4. 持久化

每轮把以下状态写入 MySQL（`server_history_pool` / `server_blacklist`）：

- `ema_score`（HistPerf）
- `risk_ema`（RiskEMA）
- `rounds`
- `blacklist` 与 `reason`

因此判定是跨轮继承的，不是一次性结果。
